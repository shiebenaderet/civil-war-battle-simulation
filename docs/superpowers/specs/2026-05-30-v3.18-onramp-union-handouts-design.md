# v3.18 — Lower the on-ramp, Union-only Historical, concrete per-battle handouts, star tiers

**Date:** 2026-05-30
**Status:** Approved design, ready for planning
**Author:** Shie (with Claude)

## Problem

Five issues surfaced from classroom-readiness review:

1. **Too much text before the simulation starts.** The `introSplash` and `modeSelection` screens largely repeat each other, and stack with the leader letter and act intro into a wall of reading before a student makes a single decision. Lower-reading students start on a bad foot.
2. **Historical Mode lets students pick the Confederacy.** For the guided, sequential Historical experience, students should play the Union (North) only. The Confederate perspective stays available in Free-play.
3. **Handouts are not concrete enough.** The current Battle Journal captures "key events" and "why it mattered" per *act*. It should instead be a concrete **log of what the student chose at each station (battle)**, with a **Yes/No field for whether their choice matched history**, a **per-battle "why it mattered" box** holding the one key idea for that battle, and an **act-end reflection prompt whose wording matches the website prompt at the student's reading tier**.

4. **The after-battle flow buries the takeaway.** The post-battle reveal does not clearly hand students the one key idea they need to answer the act question, and it routes everyone through historical voices / video / bigger-picture analysis as if mandatory. The flow should **lead with "why it mattered"** (the per-battle key idea) and make voices/video/extra resources **optional**.

5. **The reading-tier labels are opaque.** The pills show single letters (E / B / I / A) with no signal of order. They should become a 1–4 **star rating** with **support-level names**, matched on the handouts.

The handout (Part 3) and the after-battle flow (Part 4) are two halves of one idea: the screen hands each student **one key idea per battle** ("why it mattered"), they write it down, and that becomes the evidence they reason from at the act-end reflection. Parts 1 and 2 are small, low-risk on-ramp fixes; Parts 3 and 4 are the coupled "concrete capture" work.

## Non-goals

- No change to Free-play mode mechanics or its side selection.
- No change to the leader letter content (it is good, in-character text that introduces vocab; it stays).
- No change to the act-intro screen content.
- No new reflection prompt *text* is authored. The handout reuses prompt text that already exists in the game data.
- No new per-battle "key idea" text is authored. The on-screen takeaway and the handout "why it mattered" model answer both reuse the existing per-tier `battle.historical.keyFact.{tier}` field.

## Part 3 — Concrete per-battle handouts

**Change:** Rebuild the Battle Journal as a **per-battle log grouped under act headings**, delivered as **four tier-specific files** (one per game reading tier).

### Structure

**Log section (page 1+):** Four act sections with Act I–IV headings. Under each heading, **one row per battle** in that act (13 rows total, grouped 3 / 3 / 3 / 4). Each row has three fields:

| Field | Content |
|---|---|
| **My choice** | Blank line; student writes the strategy they picked at that battle. |
| **Matched history?** | Two checkboxes: ☐ Yes ☐ No. Student self-checks against the game's "this matched history" feedback (the game already computes `wwydMatchedHistory`). |
| **Why it mattered** | Blank line(s) below the row; student writes the one key idea for that battle. The game hands them this idea on screen (see Part 4) — sourced from `battle.historical.keyFact.<tier>`. This is the raw material students draw on to answer the act-end reflection question. |

Each battle row is labeled with the battle name (e.g. "Fort Sumter", "Bull Run") so students know which station maps to which row.

**Why the "why it mattered" box matters:** the act-end reflection question is only answerable if students have accumulated concrete takeaways along the way. The per-battle "why it mattered" line gives them 3–4 key ideas per act to reason from, so the reflection prompt is grounded in their own notes rather than recall from memory.

**Act-end reflection (4 total):** After the last battle row in each act, print **one reflection prompt** for that act. The prompt text is lifted **verbatim from the game data**, from that act's reflection battle, at the tier matching the handout:

| Act | Reflection battle | Data path |
|---|---|---|
| I | Shiloh (idx 2) | `battles[2].historical.reflection.<tier>` |
| II | Chancellorsville (idx 5) | `battles[5].historical.reflection.<tier>` |
| III | Chickamauga (idx 8) | `battles[8].historical.reflection.<tier>` |
| IV | Appomattox (idx 12) | `battles[12].historical.reflection.<tier>` |

Reflection prompts get blank writing lines sized to the tier (more lines/scaffolding for lower tiers).

**Essay builder (page 2):** Keep the existing "How did the Union win?" essay-builder section (prompt, thesis frame, evidence rows, Q3/Q4, word bank), scaled per tier — heaviest scaffolding (word bank, sentence starters) on ★ Most Support, lightest on ★★★★ Extra Challenge.

### Tier → file mapping (four files)

Display names and stars are defined in Part 5; data keys are unchanged.

| Stars | Data key | Display name | Handout file | Reflection prompt key |
|---|---|---|---|---|
| ★ | `extra` | Most Support | `battle-journal-extra-support.html` | `extra` → falls back to `beginner` (no `extra` key exists on reflection prompts) |
| ★★ | `beginner` | More Support | `battle-journal-some-support.html` | `beginner` |
| ★★★ | `intermediate` | Standard | `battle-journal-standard.html` | `intermediate` |
| ★★★★ | `advanced` | Extra Challenge | **`battle-journal-advanced.html` (NEW)** | `advanced` |

**Note on Most Support (★) reflection text:** the four reflection prompts in the data have `beginner` / `intermediate` / `advanced` keys but **no `extra` key**. Per the game's existing fallback chain (`extra → beginner`), the Most Support handout prints the `beginner` prompt wording. This is consistent with how the game itself resolves `extra`-tier reflections.

**The reflection prompts are copied as static text into each handout file** (the handouts are standalone HTML printables with no access to the game's JS data objects). At build time the implementer reads the verbatim text from `js/data/battles.js` and pastes it into the matching handout. If game prompt text changes later, handouts must be updated to match (document this coupling in the handout file as a comment).

### Build order

1. Build the **★★★ Standard** (`intermediate` / `standard`) handout first: per-battle log grouped by act + 4 act reflections + essay builder. Get sign-off.
2. Port the pattern to **★ Most Support**, **★★ More Support**, and the new **★★★★ Extra Challenge** file, scaling scaffolding per tier and swapping in the tier-matched reflection text.

### Menu wiring

- `index.html`: add a fourth handout menu item, "★★★★ Extra Challenge", linking to `handouts/battle-journal-advanced.html` (`target="_blank"`). Relabel the existing three menu items to their new display names (Most Support / More Support / Standard) per Part 5.
- `js/app.js`: add the new menu button id to the handout-link wiring array (currently `['handoutStandardMenuBtn', 'handoutSomeSupportMenuBtn', 'handoutExtraSupportMenuBtn']`).

### Acceptance

- Four handout files exist; each prints clean on B&W letter (existing `@media print` discipline preserved).
- Each file's four act reflections match, word-for-word, the game prompt for that act's reflection battle at that tier (★ Most Support uses `beginner` text).
- Each act section lists exactly its battles (3/3/3/4), each row with a "My choice" line and ☐ Yes ☐ No "Matched history?".
- Settings menu links to all four handouts.

## Part 4 — Pared-down "why it mattered" after-battle flow

**Change:** Reshape the after-battle reveal so it leads with **one key idea to remember** ("why it mattered"), and make the deeper content (historical voices, the Battlefield Trust video, bigger-picture analysis, extra resources) **optional/collapsed** rather than a mandatory wall.

**Why:** This closes the loop with Part 3. The screen tells each student the one key idea for the battle; they write it in the handout's "why it mattered" box; that becomes the evidence they reason from at the act-end reflection. The voices/videos stay (they are valuable) but become opt-in so the core takeaway is not buried.

### Existing flow (verified)

The after-battle reveal is a step machine in `js/ui.js` driven by `narrativeStep`:

- **Step 0** Briefing (intel + situation)
- **Step 1** Your Call (WWYD — blocks until a choice is made)
- **Step 2** Feedback (your choice vs. the historical choice; "Same call as <commander>" / "You chose a different path")
- **Step 3** What Happened (outcome + tech)
- **Step 4** Voice + Bigger Picture — **already collapsed by default for `beginner`/`extra` tiers** via `setupCollapsibleSection(...)`
- **Step 5/6** advance (or grouped reflection on the 4 reflection battles)

So "make voices optional" is partly built: the collapse mechanism exists for low tiers at step 4.

### Changes

1. **Surface the key idea as a prominent, ALWAYS-VISIBLE takeaway.** At the What-Happened beat (step 3 / `sectionHappened`), display `battle.historical.keyFact.<tier>` as a visually distinct "Key idea — write this in your journal" callout, shown to **every tier**. This is the one sentence the handout's "why it mattered" box expects. It already exists per tier for all 13 battles; no new authoring.
   - **Important gap this fixes (found in research):** today `keyFact` lives in the *collapsed* Bigger Picture section and is **entirely hidden at the two low tiers** (`js/ui.js:1357`, `isLowReadingTier`). So Most Support and More Support students never see the key idea at all. The new callout is a **separate, always-visible element** in `sectionHappened`, independent of the old collapsed box, so the takeaway is never hidden for anyone.
   - Mirror the existing handout-nudge pattern (`act-review-handout-nudge` / `populateNoteNudge`) so the visual language ("write this on your handout") is consistent.
2. **Make Voice + Bigger Picture collapsed-by-default for ALL tiers**, not just `beginner`/`extra`. Change the `setupCollapsibleSection('voiceHeading', ...)` / `('bigPictureHeading', ...)` calls at step 4 so the third argument (start-expanded) is `false` for every tier. Students can expand "Hear the voices" / "The bigger picture" if they want more; the default keeps the flow tight.
3. **Video + extra resources stay, framed as optional.** The Battlefield Trust video and any extra-resource links remain available on the battle screen (e.g. in the map/visual tabs and the voices section) but are not gating steps. No removal — just ensure nothing forces a student through them to advance.

### Files / touch points

- `js/ui.js`: at the What-Happened step, populate and show a key-idea callout from `keyFact.<tier>`; flip the two `setupCollapsibleSection` start-expanded flags to `false` for all tiers at the Voice/Bigger-Picture step.
- `index.html`: add the key-idea callout element to the battle screen markup (near `sectionHappened`).
- `css/styles.css`: style the key-idea callout to match the handout-nudge / PAT visual language.

### Acceptance

- After each battle, a clearly styled "Key idea" callout shows the per-tier `keyFact` sentence and nudges students to write it in the journal's "why it mattered" box.
- The callout text matches, word-for-word, the `keyFact.<tier>` field for that battle (and the handout's model answer, if printed, uses the same field).
- Voice and Bigger Picture are collapsed by default for every tier; expandable on demand.
- No step in the after-battle flow forces a student through the video or extra resources to advance.

## Part 5 — Star-rating tier labels

**Change:** Replace the opaque single-letter reading pills (E / B / I / A) with a **1–4 star rating** that communicates difficulty order at a glance, paired with **support-level names**. Apply the same labels on the handouts.

**Why:** "E B I A" gives no signal that E is easiest and A is hardest. Stars are universally read as "more = harder." Support-level names ("Most Support" … "Extra Challenge") describe the *scaffolding*, not the student, which is kinder framing.

**This is a display-label change only.** The data keys stay `extra` / `beginner` / `intermediate` / `advanced`. No save-format change, no data migration, no `resolveDifficulty` change.

### Label mapping (single source of truth)

| Stars | Data key | Display name | Handout file |
|---|---|---|---|
| ★ | `extra` | Most Support | `battle-journal-extra-support.html` |
| ★★ | `beginner` | More Support | `battle-journal-some-support.html` |
| ★★★ | `intermediate` | Standard (default) | `battle-journal-standard.html` |
| ★★★★ | `advanced` | Extra Challenge | `battle-journal-advanced.html` (new) |

### Accessibility

Stars are decorative for sighted ordering. The **tier name carries the meaning for assistive tech**: each pill keeps the display name in `aria-label` / `title` (e.g. `aria-label="Standard reading level, 3 of 4"`), and the stars themselves are `aria-hidden`. This was the chosen approach (stars visible; name in aria/title). Selected state still uses `aria-pressed`/`aria-checked` as today.

### Files / touch points

- `index.html`: the reading-pill group (~lines 189–192) — replace the letter text with star glyphs (or CSS-rendered stars), set `aria-label`/`title` to the display name + position, keep `data-level` keys unchanged. Update the `difficulty-selector` pills on `sideSelection` (~lines 419–422) the same way, and the `difficultyHint` text.
- `css/styles.css`: style the star pills (`.reading-pill`, `.difficulty-pill`) so 1–4 stars render evenly and the active state is clear; keep dyslexic-font and print rules intact.
- `js/ui.js` / `js/app.js`: anywhere a tier *word* is shown to students (e.g. saved-game mode label, difficulty hint text) use the new display names. The four handout files' header tags use the matching "★★★ Standard" form. Audit for hardcoded "Beginner"/"Intermediate"/"Advanced" display strings.
- **Handouts (all four):** header tag shows the stars + display name (e.g. "★★★ · Standard"). Replace the old "Standard · Large Text" style tags.

### Acceptance

- Reading pills show 1–4 stars in ascending order; the active tier is visually obvious.
- Screen readers announce the tier name and position, not "star star star."
- Each handout header shows the matching star count + display name.
- No data/save changes; switching tiers still works exactly as before (verify a mid-game tier switch).
- Dyslexic font mode and B&W print still render the pills/headers correctly.

## Sequencing & risk

- **Part 1** and **Part 2** are independent, small, and low-risk. They can ship together ahead of Parts 3–4 to improve the on-ramp before launch.
- **Parts 3 and 4 are coupled** and share one field (`keyFact.<tier>` drives both the on-screen key-idea callout and the handout's "why it mattered" model answer). Build Part 4 (surface the key idea on screen) and the Intermediate handout together so the screen-to-paper loop can be tested end to end, then port to the other three tiers.
- **Part 3** is the heaviest lift (four print documents). **Part 4** is a contained change to an existing step machine (no new flow; reuses the existing collapse mechanism and note-nudge pattern). **Part 5** is a display-only relabel (stars + support-level names); low risk but touches both screen pills and all four handout headers, so it should land alongside the handout work to keep labels in sync.
- Chromebook QA (per project notes, the top pre-launch priority) should cover: the new boot path (lands on mode select), the Union-only Historical flow, the key-idea callout rendering at each tier, the star-rating pills (including screen-reader announcement), and the four handouts printing clean on B&W letter.

## Build plan (3 chunks, continuous run with checkpoints)

The work runs in three self-contained chunks, each ending in a verifiable, working state. The user reviews at each chunk boundary.

**Chunk A — On-ramp (Parts 1, 2, 5).** Drop `introSplash`, make Historical Union-only, replace tier pills with star + support-level labels. Small, low-risk, ships the day-one wins. No dependency on the handout work.

**Chunk B — Extract, clean & verify (the re-sync step).** DONE for planning: the current text was read verbatim from `js/data/battles.js` for every tier and committed to `docs/superpowers/specs/2026-05-30-v3.18-verified-tier-text.md` (the single source of truth). It covers:
- `keyFact.<tier>` for all 13 battles (drives the on-screen key-idea callout AND the handout "why it mattered" model answer). **All 13 have all four tier keys including `extra`** (research corrected the earlier assumption).
- `reflection.<tier>` for the 4 reflection battles (idx 2, 5, 8, 12). **No `extra` key exists** on any reflection; Most Support uses `beginner` via fallback.

**Em-dash cleanup (decided):** the source strings contain em dashes (`—`), violating the no-em-dash convention. Chunk B **cleans the em dashes in `battles.js` itself** (targeted edits to the ~15 flagged strings; replace `—` with the punctuation the sentence implies). The cleaned text is what Chunk C copies onto the handouts, so screen and paper both read from the cleaned source and stay in parity. Flagged strings are marked **[EM]** in the verified-tier-text file.

This step exists specifically so the handouts **re-sync from real (and now convention-clean) data** rather than from any prior assumption about the wording.

**Chunk C — Capture (Parts 3, 4).** Using the Chunk B table as the source: add the on-screen key-idea callout + collapse-by-default flow (Part 4), then build the four handouts (Part 3) — Standard tier first for sign-off, then port to the other three. Every piece of printed/displayed tier text traces back to the Chunk B extraction.

Each handout file notes this coupling in a comment; if game text changes later, re-run the Chunk B extraction and update the handouts.
