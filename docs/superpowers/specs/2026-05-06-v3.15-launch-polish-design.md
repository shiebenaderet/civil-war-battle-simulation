# v3.15 — Launch Polish Design Spec

**Status:** approved direction (Option B navbar, all C-scope features)
**Branch:** v3.15-polish (to be created)
**Target version:** v3.15.0
**Goal of this version:** ship the classroom-ready release: accessible, switchable mid-game, recoverable from accidents, and visually coherent with v3.11 Field Report.

---

## 1. Problem statement

v3.14 shipped the content and structural improvements students need; v3.15 makes the application classroom-ready. Five concrete launch-blockers:

1. **The toolbar is half-modernized.** The navbar uses Field Report tokens, but its dropdown menu still uses pre-v3.11 design tokens (rounded corners, soft shadows, old surface colors). The menu has only one item (Start Over). Bare emoji icons clash with the typewriter chrome.
2. **Dyslexic font support is gone.** Removed in v3.11's visual reset and never restored. This is an accessibility regression for a classroom tool.
3. **Reading level is locked once you start.** Students who pick the wrong level on the start screen cannot switch without losing all progress via Start Over.
4. **No font size control.** Old Standard TT at default size on a 1366px Chromebook is small for many students.
5. **No recovery from accidents.** Refresh, browser back, or "I want to redo Antietam" each result in either lost work or a full reset.

A sixth piece — text-to-speech — is added because it pairs naturally with the dyslexic font work and addresses the same population of struggling readers. It ships with explicit guardrails about voice quality variability.

A seventh — print summary — is the only end-of-game artifact students will have to discuss/turn in.

---

## 2. Architectural approach

**Tokenized accessibility state on `<html>`.** All accessibility settings (dyslexic font, font size) are exposed as `data-*` attributes on the root element. CSS reads them via attribute selectors and remaps the existing CSS variables. This means:
- No JS-driven inline styles to maintain
- No new "themes"; just remappings of existing tokens
- The Field Report aesthetic is preserved at every setting
- A single `data-font-family="dyslexic"` attribute on `<html>` swaps the entire app

**Persistent settings via localStorage.** A single object `cwSettings_v1` holds: `{ readingLevel, fontFamily, fontSize, ttsVoice, ttsRate }`. Loaded on app boot, applied to `<html>` data attributes synchronously before first paint to avoid flash-of-unstyled-content. All settings persist across sessions.

**Decoupled toolbar.** Rendering the toolbar's reading-level pills uses the same data binding as the existing start-screen pills — they share `setReadingLevel(level)` so changes propagate identically.

**TTS as a service module.** `js/tts.js` wraps `window.speechSynthesis` with: voice detection, voice list filtering (skip empty/invalid voices reported by some Chromebooks), play/pause/stop, rate control, and per-element controls. UI consumers attach a play button to specific elements and don't think about the engine.

**Refresh/back guard via `beforeunload`.** A flag `gameState.isInBattle` triggers the browser's "Are you sure?" dialog. Cleared when battle is committed/saved. Plays well with existing autosave.

**Reset Battle via existing save migration.** The save format already supports migrating mid-game. Reset Battle is implemented as: clear `gameState.battles[currentBattleIndex]` mid-battle progress + re-enter `enterBattleScreen(currentBattleIndex)`. No new data structures.

**Print summary via existing PDF export hook.** The codebase already has `exportCampaignPDF()` for the war map. We extend it: `exportReflectionSummary()` produces a print-styled HTML page with all reflections, recall answers, and study notes, then triggers `window.print()` with a print-specific stylesheet that suppresses navbar, removes background, and uses a single column.

## 3. Toolbar redesign (Option B + responsive density)

**Design constraint:** the navbar must remain a single 52px row on desktop. "Act II — 1862" subtitle moves into the battle header, freeing vertical space inside the masthead.

### Desktop layout (≥768px)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ CIVIL WAR SIMULATION              Reading [B][·I·][A]   [Aa]   [⋯]      │
└──────────────────────────────────────────────────────────────────────────┘
   ↑ title                          ↑ pill group         ↑ acc.  ↑ menu
```

- **Title block:** "CIVIL WAR SIMULATION" only. No subtitle in navbar. Same `font-serif` 700 uppercase as today.
- **Reading pills:** `[B][I][A]` segmented control, 34px tall, single border, no inner padding. Active state is solid ink fill with paper text. Inactive is transparent paper-card background, ink-muted text. The word "Reading" sits to the left as a typewriter-mono caption.
- **Aa button:** square 36px button with "Aa" text in serif. Opens accessibility panel.
- **⋯ button:** square 36px button with horizontal ellipsis. Opens menu (game actions, navigation).
- **Single row enforcement:** if title overflows, it truncates with ellipsis. Pills never wrap.

### Mobile layout (<768px)

Navbar becomes two rows:

```
┌─────────────────────────────────┐
│ CIVIL WAR              [Aa] [⋯] │
│ ───────────────────────────────│
│              Read [B][·I·][A]  │
└─────────────────────────────────┘
```

- Title shortens to "CIVIL WAR".
- Reading pills move to their own row, right-aligned. "Read" caption.
- Total height ~88px on mobile vs 52px on desktop. Acceptable because mobile users typically have more vertical space below the keyboard.

### Subtitle relocation: "Act II — 1862"

Removed from navbar. Added inside the existing `.battle-header` at the top, above the battle name, as a small typewriter-mono dateline. This is a more natural location — the act/year is contextual to the current battle, not the app.

### Settings menu (⋯) cleanup

Replace the existing rounded-corner, soft-shadow menu with Field Report tokens:

```
┌─ Menu ─────────────┐
│ NAVIGATION         │
│   War Map          │
│   Campaign Log     │
│   Help & Tutorial  │
├────────────────────┤
│ GAME               │
│   Reset This Battle│
│   Start Over       │
│   Print Summary    │  ← appears only at end of game
└────────────────────┘
```

- Sharp corners, 1px ink border, paper-card background.
- Section labels in typewriter mono uppercase 0.72rem.
- Items in serif 0.95rem.
- Danger items (Reset, Start Over) in vermillion accent on hover.
- Print Summary visible only when `gameState.isComplete === true`.

### Accessibility panel (Aa)

Opens as a modal-style overlay anchored to the Aa button (right-aligned, drops down). 280px wide on desktop, full-width on mobile.

```
┌─ Accessibility ─────────────┐
│ DISPLAY                     │
│   OpenDyslexic font   [✓]   │
│   Font size: [S][M][L]      │
├─────────────────────────────┤
│ READ ALOUD                  │
│   Voice: [Samantha    ▾]    │
│   Speed: [0.8×][1×][1.2×]   │
│   ⓘ Quality varies by       │
│     device.                 │
└─────────────────────────────┘
```

- Same Field Report tokens as the menu.
- Quality note appears only when detected voices are eSpeak-class (heuristic: voice name contains "espeak" or list has fewer than 3 voices and they have generic "en" lang codes).
- Voice dropdown is empty if no usable voices; whole READ ALOUD section hides.

## 4. Reading level switching mid-game

**Behavior:** Clicking a different pill in the navbar pill group calls `setReadingLevel('beginner' | 'intermediate' | 'advanced')`. This:

1. Updates `gameState.difficulty` (existing field).
2. Persists to localStorage (`cwSettings_v1.readingLevel`).
3. Calls the existing `applyDifficultyToCurrentScreen()` function — which already exists for the start-screen pills, just needs to be called from the navbar too.
4. Re-renders all visible content at the new reading level: battle prompts, options, feedback, outcome, reflection from history, recall questions, study guide, note nudges.
5. Updates pill active state (visual confirmation).

**Edge case 1: mid-WWYD.** If the student has selected an option but not yet clicked Continue, we re-render the prompt at the new level but preserve their selected option index (the historical option is still index 0 at any reading level — text changes, identity doesn't).

**Edge case 2: mid-recall.** Recall question text is reading-level-specific. Switching levels mid-question re-renders the question and its options. Already-attempted state (which options were tried) is reset because the questions themselves are different at different levels. A short toast: "Reading level changed. Question restarted." Acceptable because students rarely switch mid-question; if they do, restarting is the correct behavior.

**Edge case 3: mid-reflection textarea.** The student's typed reflection is preserved (it's their words, not ours). The prompt above the textarea re-renders at the new level. Their saved-to-localStorage reflection stays intact.

**Edge case 4: act review modal open.** Re-render the modal contents at the new level. Modal stays open.

## 5. Dyslexic font support

**Font:** OpenDyslexic, the user's existing preference. Self-hosted (we add the WOFF2 file to `assets/fonts/`); no Google Fonts dependency. Reason: schools sometimes block external font hosts, and OpenDyslexic isn't on Google Fonts anyway.

**Implementation:**

```css
@font-face {
    font-family: 'OpenDyslexic';
    src: url('../assets/fonts/OpenDyslexic-Regular.woff2') format('woff2');
    font-weight: 400;
    font-display: swap;
}
@font-face {
    font-family: 'OpenDyslexic';
    src: url('../assets/fonts/OpenDyslexic-Bold.woff2') format('woff2');
    font-weight: 700;
    font-display: swap;
}

html[data-font-family="dyslexic"] {
    --font-serif: 'OpenDyslexic', Georgia, serif;
    --font-sans: 'OpenDyslexic', Georgia, serif;
    --font-mono: 'OpenDyslexic', Georgia, serif;
}
```

**All text becomes OpenDyslexic when toggle is on, including typewriter chrome.** This is the deliberate choice: a student who needs OpenDyslexic for body text shouldn't have to context-switch to read smaller chrome elements (act labels, image credits, recall option letters). The Field Report identity is carried by other tokens (paper sepia, sharp corners, double-rule borders, vermillion accent) — typography is one signal, not the only one. The visual identity holds.

**Toggle behavior:** instant. Setting the data attribute swaps fonts via CSS — no reload. Persists across sessions.

**Asset size:** OpenDyslexic Regular + Bold = ~150KB total. Acceptable.

## 6. Font size control

Three sizes only: Small / Medium / Large.

```css
html[data-font-size="small"]  { --font-size-base: 0.9rem; }
html[data-font-size="medium"] { --font-size-base: 1.0rem; }   /* default */
html[data-font-size="large"]  { --font-size-base: 1.15rem; }
```

Because the existing typography uses `clamp()` with `--font-size-base` as an anchor and viewport scaling, all relative sizes rescale proportionally. We don't override individual sizes; we shift the base and let cascade do the work.

Persists across sessions. Instant. No reload.

**Caveat we're accepting:** at "Large" some battle screens will require more scrolling. This is correct — the alternative is unreadable text.

## 7. Reset Current Battle

**UI:** menu item ("Reset This Battle") inside the ⋯ menu, only visible when `gameState.currentBattleIndex` is set and the student is mid-battle (`narrativeStep > 0`).

**Confirmation:** modal dialog matching the act review modal style:

> **Reset this battle?**
> Your progress on **[Battle Name]** will be cleared. Your reflections from earlier battles are safe.
> [Cancel] [Reset Battle]

**Implementation:**
1. Set `gameState.battles[currentBattleIndex] = createEmptyBattleProgress()`.
2. Reset `gameState.narrativeStep = 0`, `gameState.wwydSelectedIndex = null`.
3. Persist to localStorage.
4. Call `enterBattleScreen(currentBattleIndex)` to re-render from step 0.

**Does NOT touch:** earlier battles' completed state, completed recalls, reflections from prior acts, side selection, name, reading level.

## 8. Refresh / back-button warning

**Trigger conditions:** `beforeunload` listener checks `gameState.isInBattle === true`. This flag is:
- Set when entering a battle screen.
- Cleared when the battle's `committed` flag is set (after reflection saved or recall completed).
- Cleared when navigating to the war map or campaign log via menu.

**Browser behavior:** browsers show their own "Leave site?" dialog with our short message. We don't get to fully customize the text on modern browsers — they'll show "Changes you made may not be saved" or similar. That's fine; the goal is the speed bump.

**Edge cases:**
- Student finishes a battle and clicks Continue: `committed` flag set, no warning when they click into next battle and the page loads.
- Student finishes the entire game: end screen sets `gameState.isInBattle = false`. No warning when closing.
- Page error / actual bug: localStorage autosave still has the latest state. Warning is supplementary, not the primary protection.

## 9. Read-aloud (TTS)

**Engine:** `window.speechSynthesis` only. No paid APIs, no audio files, no service worker.

**Module:** `js/tts.js` exports:
```js
TTS.init()                         // populate voice list (async)
TTS.getVoices()                    // returns filtered voice list
TTS.speak(text, opts)              // opts: { voice, rate, onEnd }
TTS.pause(), TTS.resume(), TTS.stop()
TTS.isAvailable()                  // false if no usable voices
TTS.qualityWarning()               // returns string|null
```

**Voice filtering:** browsers report many junk voices on Chromebooks. We filter:
- Drop voices where `voice.lang` doesn't start with "en".
- Drop voices with names containing "espeak" (low quality).
- If after filtering we have 0 voices, `isAvailable()` returns false and the entire Read Aloud section hides.

**Quality warning heuristic:** if filtered voice list contains only voices with `localService === false` (network voices, often slow) or only generic names, surface "Quality varies by device" in the panel.

**UI placement of play buttons:**

Each readable text section gets a small play button in the top-right corner: a 28px square with a typewriter-style "▶ Read" label. When playing, becomes "■ Stop". One play button per:
- Battle situation paragraph (per-side, per-reading-level)
- WWYD prompt
- Feedback sub-section
- Outcome sub-section
- Reflection from history sub-section
- Recall question (with options read in sequence)
- Note nudges

**State machine:** only one TTS plays at a time. Clicking play on section B while section A is playing stops A and starts B. Clicking play on the same section while it's playing stops it.

**Settings persistence:** chosen voice and rate persist. On boot, if previously chosen voice is no longer available (different device or browser update), fall back to first available voice.

**What we explicitly accept:**
- Quality is uneven across devices. Documented in the panel.
- TTS is a supplementary feature, not a primary feature. The app must work fully without it.
- We do not build TTS for non-English content (we don't have any anyway).

## 10. Print-friendly summary

**Trigger:** "Print Summary" item in ⋯ menu, visible only when `gameState.isComplete === true` (game finished, end screen reached).

**Output:** opens a new browser tab/window with a print-styled HTML document and immediately calls `window.print()`. Document content:

- Header: "Civil War Simulation — [Student Name]'s Campaign"
- Side: Union or Confederacy
- Reading level used
- Date completed
- For each act:
  - Act number, name, years
  - Battles played (table: name, date, decision made, historical decision, match Y/N)
  - Recall questions and the student's answers (table: question, student's answer, correct answer)
  - Student's reflection text (full prose)
- Final synthesis: completion stats, total reflections submitted

**Print stylesheet:** suppresses navbar, modal overlays, image credits; converts colors to print-safe (black text on white); single column; page-break-before on each act header.

**Implementation note:** we don't generate a PDF; we generate printable HTML. The user prints to PDF via their browser if they want a digital file. This is simpler, more reliable across devices, and gives the student/teacher control over output format.

## 11. Failure modes and mitigations

| Failure | Mitigation |
|---|---|
| OpenDyslexic font fails to load (network blocked, file missing) | `font-family` fallback to Georgia. Toggle still works, just doesn't change appearance. No JS error. |
| TTS voices empty (some Chromebooks at boot) | Read-aloud section hidden. App functions normally. |
| TTS speaks but is gibberish on a specific Chromebook | Quality warning visible in panel. Student can disable by stopping playback. |
| localStorage full or disabled | Settings revert to defaults each session. Game still saves session-only. Console warning. |
| Reading level switched mid-WWYD with selected option | Selected index preserved (historical option = index 0 at all levels). |
| Browser blocks `beforeunload` (some mobile browsers, all PWAs) | Autosave still protects work. Warning is best-effort. |
| Print blocked by browser popup blocker | Show inline notice: "Allow popups to print, or use browser File > Print." |
| Reset Battle clicked accidentally | Confirmation dialog requires explicit click. |

## 12. What we are NOT doing in v3.15

Documenting these so they don't drift in:

- No new battles, content, or reflections.
- No re-skin of existing screens beyond the toolbar/menu/modal redesign.
- No animation changes.
- No new game mechanics (campaigns, scoring, classroom mode, time tracking).
- No backend, no accounts, no analytics.
- No tests added (codebase has no test framework; not adding one for this version).
- No tutorial overhaul (existing tutorial still works; just verify it doesn't break with new toolbar).

## 13. Acceptance criteria

The release ships when:

1. Toolbar renders Option B layout on desktop and mobile, in Field Report tokens, single row on desktop ≥768px.
2. Settings menu (⋯) and Accessibility panel (Aa) both render in Field Report tokens.
3. OpenDyslexic toggle changes font in <100ms with no flash, persists across sessions.
4. Font size S/M/L changes scale all text proportionally, persists across sessions.
5. Reading level switch from navbar pill works mid-battle, mid-recall, mid-reflection, mid-modal.
6. Reset This Battle clears only current battle progress, prompts confirmation.
7. Refresh / back / close mid-battle shows browser warning.
8. TTS plays current section's content where voices are available; section is hidden where not.
9. Print Summary produces a one-page-ish printable document with all reflections + recall data.
10. Tutorial walks through new toolbar without errors.
11. Save/resume from v3.14.0 saves loads cleanly into v3.15.0 without data loss.
12. Existing tests: human walkthrough of full Act I → Act IV flow with reading level switched mid-game at least twice.
