# v3.16 Extra Support (ES) Tier Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. The bulk of work is content authoring, not code; treat each battle's ES content as one task.

**Goal:** Add a fourth difficulty tier — Extra Support (ES) — to historical mode, accessible from the same B/I/A pill row in the toolbar (becomes E/B/I/A). Targets ML/IEP students currently underserved by the Beginner tier. Reading level: 1-3rd grade controlled register. The Extra Support handout already ships at this level; this brings the in-game experience down to match.

**Architecture:** The codebase already keys all reading-level content by string (`beginner` / `intermediate` / `advanced`). Adding a fourth key — `extra` — is a config change in 4-5 code files plus content authoring across all 13 battles + 4 acts. The fallback chain (currently `difficulty || 'intermediate'`) gets one new step: ES falls back to Beginner if an ES field is missing, so partial rollout is safe.

**Tech Stack:** No new dependencies. Same vanilla HTML/CSS/JS. Content lives in the same data files (`js/data/battles.js`, `js/data/acts.js`).

**Why this matters:** Three weeks to classroom launch is too tight to write 6,000+ words of ES content from scratch. This plan stages the work so the highest-leverage pieces ship first and lower-leverage pieces fall back to Beginner content gracefully. A student selecting ES never sees an empty field; they may see Beginner-level content for some sub-screens until ES authoring catches up.

## File structure

**Modified files (code wiring):**
- `index.html` — add fourth pill (`E`) to the reading-level pill row in toolbar; add ES option to settings menu reading-level dropdown if one exists
- `css/styles.css` — pill width may need to compress slightly to fit 4 pills; add `.difficulty-pill[data-level="extra"]` styling (consider distinct visual treatment, e.g., the brand-red `--ext: #3A1208` from the handout system to signal "this is the most-supported tier")
- `js/settings.js` — add `extra` to the `READING_LEVELS` array; ensure `applyDifficultyToCurrentScreen()` re-renders correctly when switching to/from ES
- `js/game.js` — add `extra` to the difficulty validation/normalization; update `resolveSideText` callsites if any difficulty-fallback logic lives there
- `js/ui.js` — update the difficulty fallback chain in every place that does `gameState.difficulty || 'intermediate'`. Pattern: `gameState.difficulty || 'beginner'` for ES fallback, then beginner falls back to intermediate. Affects: `openActReview`, `renderActRecall`, `populateNoteNudge`, `showReflectionStep`, all the per-sub-step render calls. Best done with a single helper `function getDifficultyText(field, difficulty) { return field[difficulty] || field.beginner || field.intermediate || ''; }` and replacing inline fallbacks.
- `js/print-summary.js` — add `extra` to whatever difficulty-aware rendering it does (likely the recall question display)
- `js/tts.js` — verify TTS reads ES content; no changes expected since it reads DOM textContent

**Modified files (content authoring):**
- `js/data/battles.js` — for each of 13 battles, add `extra:` keys to all reading-level-keyed fields. This is the bulk of the writing.
- `js/data/acts.js` — for each of 4 acts, add `extra:` keys to all reading-level-keyed fields (intros, recall questions, reviews).

**New files:**
- None. ES tier is added by extending existing data structures, not new modules.

## Content scope estimate

Counted via `grep -c "beginner:" js/data/{battles,acts}.js`:
- battles.js: 208 `beginner:` keys (some are option arrays of 3 strings each, so actual string count is higher)
- acts.js: 16 `beginner:` keys (mostly long-form review markdown)

**Estimated word count for full ES coverage:** 6,000-8,000 words at 1-3rd grade reading level. Median field is ~30 words; longest fields are act review summaries (200+ words each, 4 acts × 3 levels × ~200 words now = ~800 words just for the review level).

**Reading level target:** Flesch-Kincaid grade 1.0-3.0. Practical heuristics:
- Sentences average 8-10 words. Hard cap at 14.
- One idea per sentence. No subordinate clauses.
- Words of 1-2 syllables wherever possible. Multi-syllable words must be names of people/places/events students will hear repeatedly.
- Active voice. "Lee won." not "The battle was won by Lee."
- Concrete > abstract. "Many soldiers died" not "casualties were severe."
- Names introduced with role first time: "Robert E. Lee, the South's general," then later just "Lee."

## Authoring strategy: priority order

The plan is to author in **highest-leverage-first** order so partial rollout is always safe and the most important surfaces ship first.

### Tier 1 — Must-ship before classroom launch (foundation)

> **Status: SHIPPED in v3.16.0-tier1 (2026-05-14).** Code wiring complete, all 4 acts have ES content (positioning + PAT panel + 3 recall questions + review summary). Adjacent UX work shipped in same release: prominent "Review this act" buttons, intro PAT callouts, note-nudge copy reframe.


**Code wiring (Day 1, ~2 hours):** Add the E pill, the helper function, the fallback chain. Test that selecting E with no ES content gracefully shows Beginner content. **At this point, ES tier is functional with Beginner content as fallback.** Students choosing E will see Beginner-level content but have a tier that won't break.

**Act-level content (Day 1-2, ~1,500 words):** Author ES versions of:
- 4 act intros (positioning text)
- 4 act review summaries (the content of `act.review.extra` for each act — this is the synthesis layer students reach after each act)
- 12 act recall questions (3 per act, the multiple-choice questions before reflection)

**Why these first:** The act-level content is the *synthesis* layer. A student playing on ES who reads Beginner-level battle content but ES-level act reviews will still get the big picture in language they can understand. This is the most pedagogically efficient first cut.

**Verification gate:** Run through one full act on ES tier. Confirm: pill works, mid-game switch works, no empty fields, recall flow completes, act review modal renders the ES content with the handout nudge.

### Tier 2 — Ship before classroom launch if time permits

**Per-battle teaching content (Day 3-5, ~3,000 words):** Author ES versions of the battle-level *teaching* fields (not the gameplay choices). For each of 13 battles:
- `historical.situation.extra` — what's happening at this battle
- `historical.whatHappened.extra` — what actually happened
- `historical.keyFact.extra` — the key fact card
- `historical.biggerPicture.extra` — why it mattered
- `historical.tech.description.extra` — the technology spotlight
- `voice.explainer` is already non-leveled; leave it alone

**Why second:** These are what students *read* for content. The gameplay choices and feedback are interactive but secondary to the historical narrative. Battle order matters: prioritize the 8 battles that map to the 8 vocabulary terms in the handout (Sumter, Antietam, Vicksburg, Gettysburg, Chickamauga, Wilderness, Atlanta, Sherman's March, Appomattox — that's 9 actually, but Sherman's March and Appomattox are highest-stakes for the essay).

**Verification gate:** Play through Acts I and III on ES tier; confirm reading level holds and content makes sense.

### Tier 3 — Can ship in v3.16.x patch after launch

**Per-battle gameplay content (~2,500 words):** Author ES versions of:
- `historical.whatWouldYouDo.union.prompt.extra` and Confederate equivalent
- `historical.whatWouldYouDo.union.options.extra` (3 options) and Confederate equivalent
- `historical.whatWouldYouDo.union.feedback.extra` (3 feedback strings) and Confederate equivalent
- Per-sub-step note nudges (`battles[i].notes.{feedback,outcome,reflection}.extra`)

**Why third:** Gameplay choices and their feedback are interactive and engaging at any reading level. A student on ES who plays through choices written at Beginner level will still understand the strategic concept (the words "attack" and "defend" don't need to be simplified). This tier adds polish but isn't blocking for classroom use.

## Authoring workflow

For each content batch, the workflow is:

1. **Claude drafts** the ES version of a field, given the existing Beginner/Intermediate text as context
2. **Shie reviews** for voice, accuracy, and reading level
3. **Edit in place** if Claude's draft needs work
4. **Mark the field done** and move to the next

**Quality bar examples** (the kind of cuts that matter):

| Original (Beginner) | ES Target |
|---|---|
| "Robert E. Lee has brought his army into Maryland — the war is now on Northern soil!" | "Lee took his army north into Maryland. This was the first time the war moved to the North." |
| "Burnside ordered his soldiers to charge the stone wall 14 different times." | "The Union general told his soldiers to attack the wall 14 times. Every attack failed." |
| "It was one of the most one-sided battles of the entire war." | "The South won. The North lost more than 12,000 soldiers." |

**Anti-patterns to avoid:**
- Don't dumb down history. ES students need the same *facts*; they need them in *simpler sentences*.
- Don't drop names. Lee, Grant, Sherman, Lincoln — these names appear on the handout and the student must recognize them.
- Don't drop dates. "1863" is fine at any reading level.
- Don't use "et cetera" or "for example" or any signposting that adds words without information.

## Save migration

`gameState.difficulty` may contain `'beginner'`, `'intermediate'`, or `'advanced'` from prior playthroughs. Adding `'extra'` is forward-compatible — old saves are unaffected, new saves can be either of the four values. No migration code needed; verify by loading a v3.15.x save in v3.16 and confirming difficulty is preserved.

- [ ] Print Summary at end of game includes ES content for completed playthroughs
- [ ] TTS read-aloud reads ES content correctly

- [ ] Battle Journal Extra Support handout still aligns with in-game ES tier vocabulary

## Out of scope for v3.16

- Free-play mode does not need an ES tier (it's strategic gameplay, not narrative learning, and the freeplay scoreboard isn't a teaching surface)
- The intro splash screens (game intro, Lincoln/Davis letters) — these are read once at game start and are short enough that Beginner is fine for ES students, possibly with TTS
- The settings menu copy itself (toolbar pills, accessibility panel labels) — UI chrome, not learning content
