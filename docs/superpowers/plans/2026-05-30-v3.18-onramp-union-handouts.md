# v3.18 Implementation Plan — On-ramp trim, Union-only Historical, per-battle handouts, star tiers

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lower the on-ramp (drop the intro splash), lock Historical Mode to the Union, give students one always-visible key idea per battle, rebuild the Battle Journal as a concrete per-battle log in four tier files, and relabel reading tiers as 1–4 stars with support-level names.

**Architecture:** This is a static client-side site (vanilla JS, no build step, no test framework). Game data lives in `js/data/*.js` as plain object literals. UI is render functions in `js/ui.js`; boot/wiring in `js/app.js`; state in `js/game.js` (`gameState`). Handouts are standalone printable HTML files in `handouts/`. Verification is **manual in a browser** (open `index.html`), since there is no automated test harness. One data field drives two surfaces: `keyFact.<tier>` feeds both the on-screen key-idea callout and the handout "why it mattered" box; `reflection.<tier>` feeds both the in-game grouped prompt and the handout act reflections.

**Tech Stack:** HTML, CSS (`css/styles.css`, custom-property design tokens), vanilla ES5-style JS (no modules, no framework). Git for version control. Browser for verification.

**Source of truth for all tier text:** `docs/superpowers/specs/2026-05-30-v3.18-verified-tier-text.md` (extracted verbatim from `js/data/battles.js`). Copy from there, not from memory.

**Spec:** `docs/superpowers/specs/2026-05-30-v3.18-onramp-union-handouts-design.md`
